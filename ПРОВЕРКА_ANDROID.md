# Как проверить заметки на Android

## Проще всего — свой телефон

Expo рекомендует реальное устройство для разработки: видно фактическое поведение интерфейса. Для учебного приложения можно использовать Expo Go при совпадении поддерживаемой версии SDK. Источник: https://docs.expo.dev/get-started/set-up-your-environment/

1. Установить Node.js 24 на ПК и Expo Go на телефон. Проект использует Expo SDK 57; проверить совместимость Expo Go с этой версией. Если установленная версия её не поддерживает, использовать совместимую Android-версию с официальной страницы https://expo.dev/go либо development build. Не менять SDK наугад.
2. Открыть PowerShell:

```powershell
Set-Location -LiteralPath 'C:\Users\p21fp\Documents\GitHub\SyTestCases3\2026-task4'
npm.cmd ci
npm.cmd start
```

3. Подключить телефон и компьютер к одной Wi-Fi-сети. Открыть Expo Go и отсканировать QR-код из терминала.
4. Если соединение блокирует сеть, проверить доступ Node.js к частной сети в брандмауэре. Альтернатива — `npx.cmd expo start --tunnel`; для туннеля может потребоваться дополнительный пакет и интернет.
5. Завершить сервер сочетанием Ctrl+C.

На телефоне исходные хранилища пустые. Пять демонстрационных заметок автоматически появляются только в веб-демо: они нужны для сценария юзабилити-теста.

## Сценарий проверки native-функций

| Шаг | Действие | Ожидается |
|---|---|---|
| 1 | В режиме SQLite создать заметку с заголовком, датой, временем, участниками и текстом | Заметка видна в списке и открывается |
| 2 | Изменить заголовок и содержание | Изменения сохраняются, дубля нет |
| 3 | Найти по слову, дате, времени, применить тип мероприятия | Только подходящие записи |
| 4 | Полностью закрыть приложение и открыть снова | Заметка сохранена |
| 5 | Переключить хранилище на файлы, создать другую заметку | Список независим от SQLite |
| 6 | Закрыть и открыть приложение | Выбран файловый режим, его заметка сохранена |
| 7 | Вернуться в SQLite | Первая заметка на месте |
| 8 | Нажать удалить, отменить; затем подтвердить | При отмене запись остаётся, при подтверждении исчезает |
| 9 | Попробовать пустой заголовок, 31.02.2026, 24:60 | Ошибка формы; запись не создаётся |

Результат записать с моделью устройства, версией Android, Expo Go, датой, прошедшими шагами и текстом ошибки при сбое. Пока реальный телефон/эмулятор не проверен, в отчёте не утверждать обратное.

## Если нужен эмулятор на ПК

Стандартный вариант для проекта — **Android Emulator из Android Studio**. Expo рекомендует его при отсутствии устройства: https://docs.expo.dev/workflow/android-studio-emulator/

По требованиям Google для Windows, Android Studio вместе с Emulator требует минимум 16 ГБ ОЗУ и 16 ГБ свободного места; рекомендуется 32 ГБ ОЗУ и SSD с 32 ГБ или больше свободного места. Нужна аппаратная виртуализация Intel VT-x/AMD-V; также есть требования к процессору и видеокарте. Полная таблица: https://developer.android.com/studio/install (проверено 31.10.2026).

1. Установить Android Studio с Android SDK, Platform Tools и Android Emulator.
2. В Device Manager создать виртуальный Pixel с подходящим Android-образом для процессора ПК; запустить устройство.
3. Запустить `npm.cmd start` в папке проекта и нажать `a` в терминале Expo.
4. Повторить сценарии из таблицы. Эмулятор позволяет автоматизировать native-проверки через ADB, но для этого SDK и AVD должны быть установлены и запущены.

В рамках текущей проверки эмулятор не устанавливался, настройки виртуализации не менялись. Для одной проверки учебного приложения телефон обычно удобнее, чем установка полного Android SDK.
