# Заметки встреч

Заметки для совещаний и других рабочих встреч. У записи есть заголовок, дата, время, тип встречи, участники и текст. Можно менять записи, удалять их и искать по слову, дате или времени.

[Демо в браузере](https://lightninggo.github.io/SyTestCases3/2026-task4/web-demo/) · [Руководство со скриншотами](РУКОВОДСТВО.md)

React Native, Expo SDK 57, TypeScript и Expo Router. Для телефона сделаны два хранилища: SQLite и отдельные JSON-файлы. Переключаются в настройках. Записи между ними автоматически не переносятся.

В браузере оба режима используют localStorage с разными ключами. Пять примеров появляются только в веб-версии; на телефоне сначала будет пусто. Данные браузера могут пропасть при очистке сайта или закрытии приватного окна.

## Запустить у себя

Нужен Node.js 24. Из этой папки:

```powershell
npm.cmd ci
npm.cmd start
```

На телефоне — Expo Go, совместимый с SDK 57. Телефон и ПК подключить к одной Wi-Fi-сети, затем открыть QR-код из терминала. Для браузера нажать `w`. Если сеть мешает соединению, можно попробовать `npx.cmd expo start --tunnel` — ему нужны интернет и, возможно, дополнительный пакет.

[Подробнее про телефон и эмулятор](../ПРОВЕРКА_ANDROID.md). Под Android и iOS предусмотрен общий код, но настоящий телефон пока не проверен. Успешная сборка ещё не означает, что всё проверено на устройстве.

## Что проверить руками

1. Создать запись, открыть её, поменять текст.
2. Найти по слову, дате и времени. Попробовать фильтр по типу встречи.
3. Удалить запись: сначала отменить, потом подтвердить.
4. Перезапустить приложение — запись должна остаться.
5. Переключить SQLite на файлы, создать другую запись и вернуться обратно. Списки должны быть независимыми.
6. Оставить заголовок пустым или ввести `32.07.2026` — должна появиться ошибка.

Если запись не сохранилась, текст остаётся в форме. Ошибки чтения тоже показываются, данные молча не очищаются. Автоматического восстановления повреждённых JSON нет: перед ручным исправлением нужно сохранить копию.

## Файлы

Экраны лежат в `src/app`: список — `index.tsx`, форма — `edit.tsx`, просмотр — `note/[id].tsx`, настройки — `settings.tsx`.

В `src/lib/notes.ts` тип записи, поиск и проверки даты/времени. `storage.ts` работает с SQLite и файлами телефона. `storage.web.ts` — отдельный вариант для браузера. В `web-demo/` лежит готовая веб-сборка.

## Проверки и сборка

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build:web
npm.cmd run test:browser
```

Браузерный тест требует установленный Microsoft Edge. Он сам поднимает временный сервер и открывает отдельный профиль. Проверяет создание, изменение, поиск, сохранность после перезагрузки, режимы хранения, удаление и ошибки записи. Скриншот попадает в `test-results/`, в Git эта папка не идёт.

Unit-тесты проверяют в том числе SQL на настоящем SQLite из Node.js и работу с файлами ПК через адаптеры. Это полезно для проверки логики, но native-мост Expo так не проверяется.

Для Pages путь задан в `app.json`, поле `experiments.baseUrl`: `/SyTestCases3/2026-task4/web-demo`. После изменения кода выполнить `npm.cmd run build:web` и залить обновлённую `web-demo` целиком. Подробности публикации — в [корневом README](../README.md).
