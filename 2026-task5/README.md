# Проверка удобства заметок

Материалы юзабилити-теста приложения [«Заметки встреч»](https://lightninggo.github.io/SyTestCases3/2026-task4/web-demo/) и скрипт для обработки полной анкеты. Ответы участников и итоговая презентация в репозитории не опубликованы.

## Состав

- `1_План_тестирования.md` — цели, сценарий и метрики.
- `2_Сообщение_участникам.txt` — шаблон приглашения для варианта с формой.
- `3_Вопросы_для_формы.md` — полная анкета: шесть заданий, SEQ и SUS.
- `4_analyze.py` — обработка CSV, расчёт метрик и запись `summary.txt`.
- `test_analyze.py` — тесты обработки на синтетических данных.

## Форматы теста

Полная анкета содержит шесть отдельных заданий и десять утверждений SUS. Начальное состояние демо: пять заметок в первом хранилище и пустой список в файловом режиме. Для каждого участника используется отдельное приватное окно или чистый профиль браузера.

В коротком варианте для переписки действия объединены в три блока:

1. Создание заметки и поиск срока подготовки коммерческого предложения.
2. Поиск мероприятия по дате.
3. Изменение времени встречи, удаление заметки и переключение хранилища.

Оценка лёгкости и время в коротком варианте относятся ко всему блоку. Эти ответы разбираются отдельно от полной анкеты, без распределения одной оценки между отдельными действиями. Вопросов SUS в коротком варианте нет, поэтому балл SUS для него не рассчитывается.

## Обработка CSV

Скрипт рассчитан на полную анкету. Нужен Python, сторонних зависимостей нет.

```powershell
python 4_analyze.py results.csv
```

Поддерживается UTF-8 с BOM и без него; разделитель — запятая, точка с запятой или табуляция. Заголовки начинаются с кодов из анкеты, например `[З1-итог]` и `[SUS1]`.

Значения SUS — целые числа от 1 до 5, SEQ — от 1 до 7. Неполная или неверная анкета SUS исключается из среднего SUS. Неверная оценка SEQ пропускается только в соответствующей метрике. Число пропусков указывается в отчёте.

Результат сохраняется в `summary.txt` рядом с CSV. При пустом файле, неверных заголовках или несовпадении числа столбцов обработка завершается с ошибкой; предыдущий отчёт не перезаписывается.

Контрольные ответы сверяются с допустимыми формулировками. Нераспознанные ответы перечисляются отдельно для ручной проверки: правильный ответ может быть записан другими словами.

## Тесты

```powershell
python -m unittest discover -v
```

`results*.csv` и `summary.txt` исключены через `.gitignore`. Тестовые данные в коде не относятся к реальным участникам.
